# 🏸 จัดก๊วนแบด

เว็บช่วยจัดก๊วนแบดมินตัน — เพิ่มผู้เล่น จัดคิวให้ลงคอร์ตอย่างเป็นธรรม จับคู่ดับเบิลให้ฝีมือสูสี
จับเวลาแต่ละเกม แล้วหารค่าสนามกับค่าลูกแบดตอนจบวัน

ทุกข้อความในแอปเป็นภาษาไทย

---

## โครงสร้างที่ต้องเข้าใจก่อน

แอปนี้มี 2 ชั้น ถ้าเข้าใจตรงนี้แล้วที่เหลือง่ายหมด:

```
ก๊วน (club)          กลุ่มคนที่ตีด้วยกันประจำ อยู่ถาวร
  └── วันเล่น         หนึ่งครั้งที่ไปตี มีวันที่ ราคา และผู้เล่นของตัวเอง
        └── คอร์ต     คอร์ตที่จองวันนั้น พร้อมจำนวนชั่วโมง
              └── เกม  หนึ่งแมตช์ 2 ต่อ 2
```

**คำที่สับสนง่าย 2 คู่:**

| คำ | หมายถึง |
|---|---|
| **สนาม** | สถานที่ที่ไปตี เช่น "แบดมินตันฮอลล์ A" — ตั้งไว้ล่วงหน้าในข้อมูลหลัก |
| **คอร์ต** | คอร์ตที่จองในวันนั้น ๆ พร้อมชั่วโมง — เป็นตัวคูณค่าสนาม |
| **ผู้เล่น (ข้อมูลหลัก)** | รายชื่อคนที่ใช้ข้ามวัน เลือกติ๊กตอนจัดวันเล่น |
| **ผู้เล่น (ในวันเล่น)** | คนที่ลงชื่อไว้วันนั้น เก็บชื่อ/ระดับมือแยกเป็นของตัวเอง |

---

## ใช้งานยังไง

**ตั้งครั้งแรก** → ไปหน้า **ข้อมูลหลัก** ใส่รายชื่อผู้เล่น สนาม และยี่ห้อ/รุ่นลูกแบด
ตั้งครั้งเดียวใช้ได้ทุกก๊วน

**แต่ละครั้งที่จะไปตี**

1. เข้าก๊วน → กด **สร้างวันเล่น** (ฟอร์มจะเติมค่าจากครั้งก่อนให้อัตโนมัติ ปกติกดยืนยันได้เลย)
2. ถึงวันจริง → กด **เริ่มวันเล่น** แล้วเช็คชื่อ ใครไม่มากด **"ไม่มา"** ใครมาเพิ่มก็เพิ่มหน้างานได้
3. กด **จับคู่ลงคอร์ต** ระบบเลือกคนให้เอง → กด **เริ่มเกม** เพื่อจับเวลา → จบแล้วกด **จบเกม** คนกลับเข้าคิวท้ายแถว
   จะใส่แต้มในช่องเหนือปุ่มก่อนกดจบก็ได้ (ไม่บังคับ) ใส่แล้วจะขึ้นแพ้/ชนะในแท็บสถิติ
   และแท็บ **อันดับ** ของก๊วน จดผิดแก้ได้ในแท็บประวัติระหว่างวัน
   ใต้คำว่า VS บนคอร์ตจะบอกโอกาสชนะที่ระบบคาด เช่น 53–47 ยิ่งใกล้ 50–50 ยิ่งสูสี
   ใครยังไม่พร้อมกด **พัก** ข้างชื่อ ระบบดึงคนถัดไปในคิวมาแทน ถ้าตอนนั้นคิวว่างจะเหลือช่องว่างไว้
   พอมีคนกลับเข้าคิวแล้วกด **เติมจากคิว** ในคอร์ตนั้นได้
4. กรอกค่าสนาม/ค่าลูกตอนไหนก็ได้ (จะกรอกตอนจบวันก็ได้ เพราะราคาจริงมักรู้ตอนนั้น)
5. กด **จบการเล่นประจำวัน** → ยอดเงินและสถิติถูกล็อกถาวร

**จองล่วงหน้าได้** สร้างวันเล่นของสัปดาห์หน้าทิ้งไว้ก่อนได้ จะไปโผล่ในหัวข้อ "ที่จะเล่น"

## เรื่องเงิน

```
ค่าสนาม  = ชั่วโมงรวมของทุกคอร์ต × ราคาต่อชั่วโมง
ค่าลูก   = จำนวนลูก × ราคาต่อลูก
ต่อคน    = (ค่าสนาม + ค่าลูก) ÷ จำนวนคนที่มาและร่วมจ่าย
```

**หารเท่ากันทุกคนที่มา** ไม่หารตามจำนวนเกมหรือเวลาที่เล่น
คนที่ถูกกด "ไม่มา" และคนที่ติ๊กออกจากรายชื่อผู้ร่วมจ่ายเท่านั้นที่ไม่ถูกนับ
คนที่นั่งพักทั้งวันยังจ่ายเท่าคนอื่น

**พอกดจบวัน ยอดจะถูกแช่แข็ง** ขึ้นราคาสนามครั้งหน้า ยอดของวันเก่าจะไม่ขยับตาม
เพราะมันคือเงินที่จ่ายกันไปแล้วจริง ๆ

## การจัดคิวและจับคู่

คิวเรียงตาม **คนที่เล่นน้อยสุดก่อน** ถ้าเท่ากันเอาคนที่รอนานกว่า มีสองโหมดให้เลือก:

| โหมด | ทำอะไร |
|---|---|
| **สลับคู่** (ค่าเริ่มต้น) | ดู 8 คนแรก เลือกชุดที่เลี่ยงการเจอคู่เดิมได้ดีที่สุด — **ยอมข้ามคิวเพื่อไม่ให้คู่ซ้ำ** |
| **ตามลำดับคิว** | หยิบ 4 คนแรกตรง ๆ แล้วแบ่งทีมให้ผลรวมฝีมือใกล้กันที่สุด — แต่ 4 คนที่จบพร้อมกันจะกลับลงไปด้วยกัน ถ้าคนเต็มคอร์ตพอดี (8, 12, 16) จะได้คู่เดิมทั้งวัน |

**ความเก่งเรียนรู้จากแต้มจริง** — ถ้าจดแต้ม ระบบจะปรับคะแนนความเก่ง (rating) ของแต่ละคนหลังทุกเกม
ชนะขาดได้มาก ชนะสูสีได้น้อย แพ้ทีมที่เก่งกว่าแบบสูสีก็ยังได้ แล้วใช้คะแนนนี้แทนระดับมือตอนแบ่งทีม
คนใหม่เริ่มจากระดับมือที่ตั้งไว้ ต้องเล่นที่จดแต้มสักพักถึงจะแม่น แท็บ **อันดับ** เรียงตามคะแนนนี้
เจ้าของก๊วนเลือกได้ในแท็บตั้งค่าว่าจะให้สมาชิกเห็นตัวเลขหรือไม่

**พักอย่างน้อย 1 เกม** — คนที่เพิ่งเล่นจบจะยังไม่ถูกดึงลงทันที ถ้าคนรอไม่พอจริง ๆ
ระบบเลือกคนที่พักมานานที่สุดก่อน คนมาสายจึงไม่ต้องลงติดกันจนหมดแรง

น้ำหนักการตัดสินใจของโหมดสลับคู่อยู่ในตาราง `WEIGHT` ที่ [`src/utils/pairing.js`](src/utils/pairing.js)
ปรับ 4 ตัวเลขนั้นได้เลยถ้ารู้สึกว่ามันสลับมากหรือน้อยเกินไป

การเลี่ยงคู่ซ้ำเป็นแค่ความพยายาม ไม่ใช่ข้อบังคับ — ถ้าเหลือรอคิวพอดี 4 คน ระบบก็จับให้ตามปกติ

## ติดตั้งเพื่อพัฒนา

ต้องมี Node 20+ และ project ของ [Supabase](https://supabase.com) หนึ่งอัน (แพลนฟรีพอ)

### 1. ตั้งฐานข้อมูล

เปิด **SQL Editor** ใน Supabase แล้วรันตามลำดับนี้:

| ลำดับ | ไฟล์ |
|---|---|
| 1 | `supabase/schema.sql` — ตาราง view และ RLS ทั้งหมด |
| 2 | `supabase/functions.sql` — RPC ทั้งหมด |
| 3 | `supabase/migrations/101` → `105` ตามเลข |

> `schema.sql` มีคำสั่งลบของเดิมอยู่หัวไฟล์ รันซ้ำได้เรื่อย ๆ **แต่ข้อมูลจะหายหมด**
> ถ้ามีข้อมูลจริงแล้วให้ลบ block นั้นออกก่อน

จากนั้นเปิด Realtime:

```sql
alter publication supabase_realtime
  add table players, courts, matches, match_players, sessions;
```

และไปที่ **Authentication → Providers** เปิด **Email** ไว้
(สวิตช์ "Confirm email" จะเปิดหรือปิดก็ได้ โค้ดรองรับทั้งสองแบบ — ปิดไว้จะทดสอบสะดวกกว่า
เพราะอีเมลในตัวของ Supabase จำกัดจำนวนส่งต่อชั่วโมงไว้ต่ำมาก)

### 2. รันเว็บ

```bash
cp env.example .env      # แล้วใส่ค่าจาก Supabase → Project Settings → API
npm install
npm run dev
```

```bash
npm run build     # build ขึ้น production
npm run preview   # ลองดูผลของ build
npm run lint      # eslint
```

> ⚠️ Vite อ่าน `.env` ตอนสตาร์ตครั้งเดียว แก้ไฟล์แล้ว **ต้องปิดแล้วเปิด `npm run dev` ใหม่**

โปรเจคนี้ยังไม่มีชุดทดสอบอัตโนมัติ

## Deploy

ต่อ repo เข้ากับ Vercel แล้วใส่ `VITE_SUPABASE_URL` กับ `VITE_SUPABASE_ANON_KEY`
ที่ **Settings → Environment Variables** (ติ๊กครบทั้ง Production / Preview / Development)
แล้ว **redeploy** เพราะ Vite ฝังค่าลงไฟล์ตั้งแต่ตอน build ไม่ได้อ่านตอนรัน

อย่าลืมเพิ่มโดเมนของ production ใน Supabase → **Authentication → URL Configuration**
ทั้ง Site URL และ Redirect URLs ไม่งั้นลิงก์ยืนยันอีเมลกับลิงก์รีเซ็ตรหัสผ่านจะใช้ไม่ได้

> ค่า `VITE_*` ถูกฝังลงไฟล์ JS ที่ส่งให้เบราว์เซอร์ ใครก็อ่านได้ — ปกติและปลอดภัย
> เพราะ anon key ออกแบบมาให้เปิดเผยได้ ตัวที่กันจริงคือ RLS ที่วางไว้ทุกตาราง
> **ห้ามเอา `service_role` key มาใส่เด็ดขาด** ตัวนั้นข้าม RLS ทั้งหมด

## แชร์ก๊วนให้คนอื่น

เข้าก๊วน → แท็บ **คนในก๊วน** → ใส่อีเมลที่เขาใช้สมัครแอปนี้ (ต้องสมัครไว้ก่อน)

| บทบาท | ทำอะไรได้ |
|---|---|
| **เจ้าของ** | ทุกอย่าง รวมถึงลบข้อมูลหลักและลบก๊วน |
| **จัดก๊วนได้** | สร้างและดำเนินวันเล่น เพิ่ม/แก้ข้อมูลหลักของเจ้าของ แต่**ลบไม่ได้** |
| **ดูอย่างเดียว** | ดูได้หมด แก้อะไรไม่ได้เลย |

ข้อมูลหลักผูกกับ**บัญชีเจ้าของก๊วน** ไม่ใช่กับตัวก๊วน คนที่ถูกเชิญมาช่วยจัดจึงใช้รายชื่อชุดเดียวกับเจ้าของ
(ในหน้าข้อมูลหลักจะมีแถบให้สลับว่ากำลังดูของใคร)

## โครงไฟล์

```
src/
  pages/        หนึ่งไฟล์ต่อหนึ่งหน้า — ต่อ hook เข้ากับ component
  components/   แสดงผลอย่างเดียว รับ props ไม่ยุ่งกับฐานข้อมูลเลย
  hooks/        ทุกการอ่าน/เขียนฐานข้อมูลอยู่ที่นี่ทั้งหมด
  utils/        pairing.js — logic จับคู่ ไม่พึ่งฐานข้อมูล ทดสอบได้เดี่ยว ๆ
supabase/
  schema.sql    ตาราง view RLS
  functions.sql RPC
  migrations/   การแก้ฐานข้อมูลหลังจากนั้น เริ่มที่ 101
docs/
  redesign-plan.md   เหตุผลเบื้องหลังโครงสร้างปัจจุบัน
```

**เส้นแบ่งที่ต้องรักษา:** component ห้าม `import supabase` เด็ดขาด ทุกอย่างที่แตะฐานข้อมูลต้องอยู่ใน `hooks/`
และอะไรที่แก้หลายตารางพร้อมกันต้องทำเป็น RPC เพื่อให้เป็นทรานแซกชันเดียว

รายละเอียดเชิงลึกและกฎที่ห้ามพังอยู่ใน [`CLAUDE.md`](CLAUDE.md)
